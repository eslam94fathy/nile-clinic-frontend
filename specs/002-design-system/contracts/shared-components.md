# Contract: Shared Components

What later phases can rely on. Props are illustrative of the responsibilities, and exact names are settled during implementation and
recorded in the preview. None of these fetch data, know about roles, or hold patient data themselves.

**Common rules**

- Text comes from props, which the caller translates, or from the `shared` translation namespace.
- Layout uses logical properties, and colors come from tokens.
- They render in both server and client trees unless marked **client**.

## Values: `components/shared/values/`

| Component | Props | Guarantee |
|---|---|---|
| `Money` | `value: string \| null` | FR-012, FR-016. Never converts to a number |
| `ClinicDate` | `value: string \| null` | FR-013. Shown as sent |
| `ClinicTime` | `value: string \| null` | FR-014. Shown as sent, including `24:00` |
| `Instant` | `value: string \| null`, `timeZone: string` | FR-015 |
| `LtrText` | `children` | For phone numbers, IDs, and codes: isolated, left-to-right |
| `UserText` | `children` | For stored text: isolated, direction from its content, never translated |

Formatting functions live in `lib/format` and are the only place that formats values. `formatInstant` from Phase 1 keeps its `Date`
signature, as the landing page passes it the current time. A new `parseInstant` turns the API's string into a `Date`, or `null` if it's invalid.

## Status: `components/shared/status-badge.tsx`

| Props | Guarantee |
|---|---|
| `kind`, `value` | Type-checked pair. Always shows its label. FR-018 to FR-020 |

## States: `components/shared/states/`

| Component | Props | Announced as |
|---|---|---|
| `LoadingState` | `label?` | `role="status"` |
| `EmptyState` | `title`, `description?`, `action?` | Plain content; the caller says "nothing yet" or "no matches" |
| `ErrorState` | `message`, `onRetry?` or `action?` | `role="alert"` |
| `ForbiddenState` | `action?` | `role="alert"`; fixed text |
| `NotFoundState` | `action?` | Fixed neutral text that doesn't imply a record exists |

## Page parts

| Component | Props | Guarantee |
|---|---|---|
| `PageHeader` | `title`, `description?`, `actions?` | One `h1`; actions wrap on narrow screens |
| `DataTable<Row>` | `columns`, `rows`, `getRowKey`, `caption`, `state`, `pagination?` | FR-022. `state` is `loading`, `error`, `empty`, or `ready`. No sorting, no fetching. Page links don't prefetch (ADR 0005) |
| `FilterBar` **client** | `filters`, `onApply?` | FR-023. Applies on submit, resets to page one. **`inAddress: boolean` is required on every filter**, so a screen can't put patient details in the address by forgetting a flag. A filter with `inAddress: false` goes only to `onApply`. Needs a `<Suspense>` boundary, since it reads search parameters |

`pagination` is `{ page, lastPage, total, hrefForPage }`. These are plain values, as the API's `meta` fields aren't confirmed until Phase 3.

## Forms: `components/shared/form/`

| Component | Props | Guarantee |
|---|---|---|
| `FormField` | `label`, `hint?`, `error?`, `required?`, `noMedicalDetails?`, `children` as a render function receiving input props | FR-026. Ties label, hint, and error to the input; marks required in text; errors announced |
| `FormError` | `messages: string[]` | Form-level errors; nothing dropped |

No form library is involved. React Hook Form arrives in Phase 3, and wraps these.

## Actions and feedback

| Component | Props | Guarantee |
|---|---|---|
| `ConfirmDialog` **client** | `trigger`, `title`, `description`, `confirmLabel`, `irreversible?`, `destructive?`, `pending`, `error?`, `onConfirm`, `open`, `onOpenChange` | FR-025, FR-030. Opens on Cancel. While `pending`: no double submit, no Escape. Failure shows inside and stays open |
| `Notices` **client** | Mounted once in the layout | FR-027. Follows direction and theme. Sonner's `toast` is called directly: no wrapper, since nothing yet needs one |

## Theme and direction

| Part | Guarantee |
|---|---|
| `ThemeScript` | Fixed inline script in `<head>`: FR-009 |
| `ThemeSwitch` **client** | Light, dark, or device. FR-008 |
| Theme re-apply | A layout effect, so a language switch keeps the theme (research R5) |
| `DirectionProvider` | Wraps the layout with the locale's direction, so Radix components follow it |

## Building blocks: `components/ui/`

Generated by the shadcn CLI, then formatted: `alert-dialog`, `badge`, `button`, `direction`, `input`, `label`, `native-select`, `skeleton`,
`sonner` (rewritten, research R3), `table`, `textarea`. Project guideline: don't edit these for one screen.

## Not provided, by decision

`Can` (Phase 3), `CursorPager` (Phase 11), print styles, sortable columns, custom select, charts.
