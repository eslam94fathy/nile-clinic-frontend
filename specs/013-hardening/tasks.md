**Organization**: By user story. US2's headers come first (Phase 3), though US1 and US2 are both P1, so that every later end-to-end test runs with the policy in force (plan, Order of Work). ## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on unfinished tasks)
- **[Story]**: The user story a task belongs to

## Rules for every task

- Check each API detail in the backend's `contracts/staff-auth.openapi.yaml` and `contracts/audit.openapi.yaml` (commit `dff2dca`). Never invent one. **Never change the backend.**
- **Tokens and the password never reach a response body, a non-sealed header, a URL, browser storage, or a log.** Only the route handlers in `src/app/api/auth/` touch a token.
- **A locked page sends nothing.** Unlocking sends one `POST /api/auth/unlock`, and never re-reads `GET /doctors/me/encounters/{id}` or `GET /doctors/me/patients/{id}/encounters`.
- **Prerendering stays** (ADR 0006): no `connection()`, no nonce, no change to `cacheComponents` or `partialPrefetching`.
- **Never re-create the request in `src/proxy.ts`**, and add nothing to it in this phase.
- **Branch only on status.** Never compare message text. Backend messages are shown as sent.
- All text goes in both `src/messages/en.json` and `src/messages/ar.json`, with identical keys. Names through `UserText`. Logical CSS only; colors only from tokens. No `any`. Test data is synthetic.
- Other features are used only through `public.ts` or `public-server.ts`.
- No new dependency in `package.json`. Container images are pinned to exact versions.
- Tests use role queries. `getByLabel` needs `.locator("visible=true")` after a soft navigation, as hidden pages stay in the DOM.
- Record every observed test result in this file, with the date. Never report a result that wasn't observed.
